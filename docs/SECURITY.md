# Безопасность фронтенда (фаза 1)

Проверка от 12 ноября 2026 года. Проверялся весь код в `frontend/src`, `next.config.ts`, зависимости и история git. Номера строк в находках указаны по коммиту `ab1da7e` — состоянию до исправлений.

## Что проверено

- **XSS.** Искал `dangerouslySetInnerHTML`, `innerHTML`, `eval`, `new Function`, `document.write` — их нет. Весь пользовательский текст React выводит как текст: запрос, вопросы и ответы чата, название чата, комментарий к «Не то», имя файла, почта. Подсветка найденного строится из разбиения строки, а не из HTML. Ответ чата не разбирается как разметка: в тексте распознаются только маркеры `[1]`.
- **Значения из адреса** (`q`, `mode`, `type`, `year`, `dept`, `clause`, `id`, `doc`, `next`) с `<script>`, `<img onerror>`, `"><svg onload>`, длинными строками и мусором — ничего не исполняется, вёрстка не ломается.
- **Ссылки.** Все `target="_blank"` с `rel="noopener noreferrer"`. Внешние ссылки берутся только из данных документов.
- **Редирект после входа**: `//host`, `/\host`, `/%5Chost`, абсолютные адреса, `javascript:`, табуляция и перевод строки внутри пути.
- **Доступ к `/admin/*` и `/pricing`** для гостя и студента: в `proxy.ts` и на страницах, в том числе по закодированным путям (`/%61dmin`), со слешем на конце, после правки `localStorage` и cookie.
- **Cookie** сессии и языка: флаги, срок, содержимое.
- **`localStorage`**: что хранится и что будет при битом JSON и чужой структуре.
- **Секреты**: файлов `.env` нет ни в дереве, ни в истории git; ключей и токенов нет; `NEXT_PUBLIC_` не используется, в клиентский бандл секреты не попадают.
- **Заголовки ответа.**
- **Загрузка файла в админке**: тип, размер, вывод имени.
- **Регулярные выражения из ввода**: экранирование спецсимволов, длинные запросы.
- **Зависимости**: `npm audit` отдельно для рабочих и dev.
- **Server actions** (вход, выход, смена языка): входные данные проверяются. Защиту от CSRF по заголовку Origin даёт сам Next.

Проверка в браузере: Chrome MCP и скрипты Playwright на dev-сервере и на production-сборке, 390 и 1280 px. Подробности — в разделе «Как проверялось» в `docs/DECISIONS.md`.

## Найдено и исправлено

### Важно

1. **Открытый редирект после входа.** `src/lib/auth/actions.ts:18` пропускал всё, что начинается с `/`, но не с `//`.
   - Чем опасно: ссылка `/login?next=/%5Cevil.com` после настоящего входа уводила на чужой сайт — удобно для фишинга от имени Izde. Браузер превращает `/\evil.com` в `//evil.com`, так же действуют табуляция и перевод строки внутри пути.
   - Воспроизведение: открыть `/login?next=%2F%5Cexample.invalid`, войти.
   - Исправлено: `safeNext` в `src/lib/auth/parse.ts` разбирает путь URL-парсером и пускает только адрес с тем же origin, иначе ведёт на `/`.
   - Тест: `src/lib/auth/parse.test.ts`, 10 вариантов атаки.
2. **Не было заголовков безопасности** (`next.config.ts:6`): ни CSP, ни защиты от встраивания, ни `nosniff`.
   - Чем опасно: сайт можно встроить во фрейм на чужом сайте (кликджекинг), при любой будущей XSS ничто не мешает выполнить чужой скрипт, браузер может угадывать тип файла.
   - Исправлено:
     - в `src/proxy.ts` на каждый запрос — CSP с nonce: скрипты только свои с nonce и `strict-dynamic`; стили в production только с nonce; `frame-ancestors 'self'`, `object-src 'none'`, `base-uri 'self'`, `form-action 'self'`;
     - в `next.config.ts` — `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, `X-Frame-Options: SAMEORIGIN`, `Permissions-Policy`, `Cross-Origin-Opener-Policy`; убран `X-Powered-By`.
   - Тест: `src/proxy.test.ts`. В Chrome на production нарушений CSP в консоли нет, включая подсказки и меню Radix.
3. **Сайт падал на испорченных данных в `localStorage`**: `src/lib/api/mock/chat.ts:10`, `:127`; `src/lib/api/mock/admin.ts:37`.
   - Чем опасно: валидный JSON чужой структуры (`{"a":1}`, сообщение без текста) ронял чат и аналитику. Данные в `localStorage` может поменять сам пользователь или расширение браузера.
   - Воспроизведение: `localStorage.setItem("izde.chats.<почта>", '{"a":1}')`, открыть `/chat`.
   - Исправлено: `src/lib/api/mock/valid.ts` проверяет структуру чатов, сообщений, ссылок, ролей, отметок и счётчика. Битые записи отбрасываются, целые остаются. Ссылка на несуществующий документ больше не даёт необработанной ошибки.
   - Тест: `src/lib/api/mock/storage.test.ts`.

## Что осталось и почему

- **Подмена роли в cookie открывает админку.** Проверено: студент, вписавший `"role":"admin"` в `izde_session`, попадает на `/admin`. На моках это неустранимо по смыслу: вход без пароля, роль выбирают на форме, любой и так может войти админом. Подпись cookie без настоящей аутентификации ничего бы не защитила. Правка `localStorage` админку не открывает.
- **Cookie сессии читается из JS** (`httpOnly` выключен). Мок хранит историю чатов по почте из cookie. В cookie только почта и роль, секретов нет.
- **Всё, что меняет админ, хранится в браузере**: тариф, роли, счётчик вопросов. Пользователь может поправить `localStorage` и, например, обнулить счётчик вопросов. Это свойство мока, а не сервера.
- **Проверка файла только на клиенте.** Браузер определяет тип по расширению, содержимое не проверяется.
- **`npm audit`: в рабочих зависимостях 0, в dev 8 moderate.** Это одна уязвимость: `minimatch` 10.x в `typescript-eslint` (GHSA-g3hv-75wg-m249, отказ в обслуживании на специально составленном glob-шаблоне). Она касается только линтера и наших же шаблонов, в сборку не попадает. Исправления в 10.x нет, а `npm audit fix --force` откатил бы `eslint-config-next` на 15-ю версию. Обновлены без смены мажорных версий: react и react-dom 19.3.0 → 19.3.1, tailwindcss и `@tailwindcss/turbopack` 4.3.3 → 4.3.5. TypeScript 7 и `@types/node` 26 — мажорные, не трогал.
- **В dev CSP мягче**: `'unsafe-eval'` для скриптов (нужен React для стеков ошибок) и `'unsafe-inline'` для стилей (оверлей ошибок Next). В production их нет.
- **HSTS не выставлен.** Его отдаёт хостинг по HTTPS: на Vercel — автоматически. На `http://localhost` он бессмыслен.
- **Нет ограничения частоты запросов**: сервера нет.

## Что обязательно сделать в фазе 2

1. **Сессия.** Выдаёт бэкенд: `httpOnly`, `Secure`, `SameSite=Lax`, подписанная или с идентификатором серверной сессии, срок жизни и ротация, выход гасит сессию на сервере. Мок-cookie `izde_session` и чтение её из JS (`lib/api/mock/browser.ts`) удалить.
2. **Настоящий вход.** Вход через аккаунт вуза или пароль с хешем (argon2/bcrypt), ограничение попыток. Роль берётся из базы, а не из формы.
3. **Проверка роли на сервере** в каждом обработчике `/admin/*`, `POST /docs`, `POST /billing/checkout`, `PATCH /admin/users/:email`. `proxy.ts` и layout оставить как удобство интерфейса, но не как защиту.
4. **Доступ к чатам по владельцу.** Сервер отдаёт и меняет чат только его автору: проверка `chatId` против пользователя, защита от IDOR.
5. **Лимиты на сервере**:
   - вопросы в чат в день — по тарифу, на пользователя;
   - частота поиска и чата;
   - попытки входа;
   - число и размер загрузок.
6. **Проверка файлов на сервере**:
   - лимит размера;
   - сигнатура (`%PDF-`, ZIP с `word/document.xml`), а не расширение;
   - разбор в изолированном процессе ML-сервиса;
   - хранение вне раздачи статики со случайными именами;
   - отдача с собственным `Content-Type` и `Content-Disposition`.
7. **Ответы LLM**:
   - отвечать только по найденным фрагментам;
   - проверять, что `citations` указывают на реальные пункты;
   - выводить ответ текстом, без сырого HTML (если появится Markdown — без HTML и со списком разрешённых тегов);
   - помнить о prompt injection из текста документов и вопросов.
8. **Проверка ввода на сервере**: длина `q` и вопроса, белые списки фильтров и режима, только параметризованные запросы к PostgreSQL и pgvector.
9. **Ссылки на документы с сервера** — только https, адрес собирать на сервере. `safeExternalUrl` на клиенте остаётся второй линией.
10. **Заголовки.** CSP оставить, в `connect-src` добавить адрес бэкенда, подключить `report-to` для отчётов о нарушениях. HSTS на хостинге.
11. **Секреты** (ключ LLM, база, оплата) — только в переменных окружения сервера, никогда через `NEXT_PUBLIC_`. В CI — `npm audit --omit=dev` и обновления зависимостей.
12. **Журналы** без персональных данных и текста вопросов, если на это нет согласия.
